# Sakila Sales API

A strict-TypeScript REST API over the PostgreSQL **Sakila** sample database — built as a teaching project, structured like production: layered routes → controllers → services, with a typed data layer powered by **Drizzle ORM**.

This is the **backend half of a two-part full-stack project**. Its companion frontend — [Sakila Angular](https://github.com/rajeshgajra19889/sakila-angular) — consumes this API (and nothing else), so the pair form a complete, deployable stack: Angular UI → Express API → PostgreSQL.

## Stack

- **Node.js** v24 — runtime
- **Express 5** — HTTP framework
- **TypeScript** (strict mode, `NodeNext` module resolution)
- **Drizzle ORM** — typed query builder (every query is a builder, zero raw SQL at runtime)
- **PostgreSQL 18** — database (Sakila schema)
- **tsx** — watch-mode TypeScript dev runner

## Features

- **Films — full CRUD**
  - Paginated listing (`page`, `pageSize`) with a totals envelope
  - Substring **search** (`title ILIKE …`, parameterized)
  - **Sort** on any column with an injection-proof whitelist (`film_id`, `title`, `release_year`, `rental_rate`)
  - Create / update / delete with proper REST semantics (201 / 200 / 204 / 400 / 404)
- **Top-rented ranking** — a three-table aggregate (`rental` → `inventory` → `film`) joined and grouped through Drizzle builders
- **Customers** — paginated-first query surface
- Migrations generated by **drizzle-kit** (`drizzle/` folder)

## API

| Method | Endpoint | Description |
|---|---|---|
| GET | `/films?page=1&pageSize=10&search=ace&sortBy=title&sortOrder=desc` | Paginated film list |
| GET | `/films/:id` | Single film (200 / 404 / 400) |
| POST | `/films` | Create film (201) |
| PUT | `/films/:id` | Update film (200 / 404) |
| DELETE | `/films/:id` | Delete film (204 / 404) |
| GET | `/top-rented` | 10 most-rented films |
| GET | `/customers` | First 20 customers |

## Getting started

**Prerequisites:** [PostgreSQL](https://www.postgresql.org/) with the [Sakila](https://dev.mysql.com/doc/sakila/en/) sample database imported.

1. Install dependencies

   ```sh
   npm install
   ```

2. Configure the database — environment variables, identical to what `pg` reads:

   ```sh
   cp .env.example .env
   ```

   ```sh
   PGUSER=postgres
   PGPASSWORD=your_password
   PGDATABASE=sakila
   PGHOST=localhost
   PGPORT=5432
   ```

3. Run it

   ```sh
   npm run dev      # tsx watch — development, hot reload
   ```

   or build + start (pure Node, no dev tooling):

   ```sh
   npm run build
   npm start
   ```

## Project structure

```
src/
├── db.ts               # pg pool + Drizzle client (typed schema attached)
├── db/
│   └── schema.ts       # Drizzle table definitions — the data contract
├── server.ts           # boot (listen)
├── app.ts              # Express switchboard: middleware + router mounts
├── controllers/        # HTTP layer — parsing, status codes
├── services/           # data layer — Drizzle queries, same vocabulary as the DB
└── routes/             # URL → controller wiring
drizzle/                # generated migrations
```

## Why it's built this way

- **Part of a full-stack pair** — this API is consumed by the [Sakila Angular](https://github.com/rajeshgajra19889/sakila-angular) frontend. The two repos share the same data contract (`{ items, total, page, pageSize }`, the `Film` shape) and evolve together.
- **Strict TypeScript end to end** — controllers, services, and ORM types agree at compile time (a renamed column is a build error, never a 3 a.m. runtime surprise).
- **Layered, not lumped** — routes know URLs, controllers know HTTP, services know SQL. Each layer has one job.
- **Contracts before leaks** — the API envelope (`{ items, total, page, pageSize }`) is fixed; the Drizzle migration changed the data layer without touching the frontend.
